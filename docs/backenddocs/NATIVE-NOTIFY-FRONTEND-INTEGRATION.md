# Native Notify Frontend Integration Guide (React Native / Expo)

This guide explains how to integrate NativeNotify into the Inspire Wallet frontend (built with React Native / Expo) so that users can receive the push notifications generated by the backend.

## 1. Installation

First, install the NativeNotify SDK in your Expo project:

```bash
npx expo install native-notify
```

## 2. Basic Setup (App.js / App.tsx)

In your main entry file (usually `App.tsx` or `_layout.tsx` if using Expo Router), initialize NativeNotify. You will need the `App ID` and `App Token` from your NativeNotify dashboard.

```tsx
import registerNNPushToken from 'native-notify';

export default function App() {
  // Initialize Native Notify
  // Replace YOUR_APP_ID (number) and 'YOUR_APP_TOKEN' (string) with the credentials from the NativeNotify dashboard.
  registerNNPushToken(YOUR_APP_ID, 'YOUR_APP_TOKEN');

  return (
    <YourAppRootComponent />
  );
}
```

## 3. Registering the User (Indie Push)

The backend sends notifications directly to specific users using their `userId`. For the frontend device to receive these notifications, it must register the logged-in user's ID with NativeNotify as their "Indie Sub ID".

You should do this immediately **after the user successfully logs in**.

```tsx
import axios from 'axios';
import { registerIndieID } from 'native-notify';

// Example Login Function
async function handleLogin(email, password) {
  try {
    const response = await axios.post('YOUR_BACKEND_URL/auth/login', { email, password });
    const { user, access_token } = response.data;
    
    // 1. Save Token to SecureStore / AsyncStorage
    await saveToken(access_token);
    
    // 2. Register the device to this User ID for Push Notifications
    // The user.id MUST match the exact UUID stored in the database.
    registerIndieID(
      user.id,             // The SubID (the exact string User ID from the database)
      YOUR_APP_ID,         // NativeNotify App ID (Number)
      'YOUR_APP_TOKEN'     // NativeNotify App Token (String)
    );

    // 3. Navigate to Main App screen
    navigation.navigate('Home');
  } catch (error) {
    console.error('Login Failed', error);
  }
}
```

## 4. Unregistering on Logout

To ensure a user doesn't receive notifications on a device after they have logged out, you must unregister their ID.

```tsx
import { deleteIndieID } from 'native-notify';

async function handleLogout(userId) {
  // 1. Unregister Push Notifications for this device
  deleteIndieID(userId, YOUR_APP_ID, 'YOUR_APP_TOKEN');
  
  // 2. Clear local storage / tokens
  await clearTokens();
  
  // 3. Navigate to Login screen
  navigation.navigate('Login');
}
```

## 5. Fetching Notification History

If a user clears their notifications or misses a push notification, they can still view all past notifications by querying the backend API.

Create a "Notifications" screen in your app that fetches from the backend we just built:

```tsx
import React, { useEffect, useState } from 'react';
import { View, Text, FlatList } from 'react-native';
import axios from 'axios';

export default function NotificationsScreen({ token }) {
  const [notifications, setNotifications] = useState([]);

  useEffect(() => {
    fetchNotifications();
  }, []);

  const fetchNotifications = async () => {
    try {
      const response = await axios.get('YOUR_BACKEND_URL/notifications?limit=20', {
        headers: { Authorization: `Bearer ${token}` }
      });
      setNotifications(response.data);
    } catch (err) {
      console.error(err);
    }
  };

  const markAsRead = async (id) => {
    try {
      await axios.patch(`YOUR_BACKEND_URL/notifications/${id}/read`, {}, {
        headers: { Authorization: `Bearer ${token}` }
      });
      // Update local state to show it as read
      setNotifications(prev => prev.map(n => n.id === id ? { ...n, isRead: true } : n));
    } catch (err) {
      console.error(err);
    }
  };

  return (
    <FlatList
      data={notifications}
      keyExtractor={item => item.id}
      renderItem={({ item }) => (
        <View style={{ opacity: item.isRead ? 0.6 : 1, padding: 16 }}>
          <Text style={{ fontWeight: 'bold' }}>{item.title}</Text>
          <Text>{item.message}</Text>
          <Text style={{ fontSize: 12, color: 'gray' }}>{new Date(item.createdAt).toLocaleString()}</Text>
        </View>
      )}
    />
  );
}
```

## 6. Automatic Notification Triggers

The backend has been deeply integrated to automatically fire push notifications (and save them to the database history) for the following system events. The React Native frontend does not need to do anything special to trigger these; they happen automatically as long as the user's device is registered on login:

1. **Top-Ups (Deposits):** Sent when an Admin Approves or Rejects a top-up request.
2. **Withdrawals:** Sent when an Admin Approves or Rejects a withdrawal request.
3. **Transfers (Peer-to-Peer):** Sent to the recipient when another user transfers funds to them.
4. **KYC Applications:** Sent when an Admin Approves or Rejects a user's KYC application.
5. **Customer Support Tickets:** Sent to the user when an Admin replies to their ticket. (Also triggers an alert for assigned admins when the user replies).
6. **Time Deposits:** Sent when a Time Deposit setup is approved, when a dividend is paid out, and when the principal matures.
7. **Direct Support Messages:** Sent when an Admin sends a direct internal message to the user.

## 7. Admin Portal Integration (React / Next.js)

The Admin portal usually doesn't *receive* push notifications on mobile devices, but rather *monitors* and *triggers* them. 

Since the heavy lifting (triggering `NativeNotify` and saving to the database) is fully automated in the **Backend NestJS server**, the Admin Portal itself does **NOT** need the `native-notify` SDK installed if admins are just approving/rejecting requests.

When an Admin clicks **"Approve"** on a withdrawal or top-up in the React admin dashboard, it hits the backend API, and the backend automatically fires the `NativeNotify` request to the specific user's mobile device.

### Sending Custom Admin Notifications
If you want Admins to manually type and broadcast a notification to a specific user from the Admin React dashboard, you can add an endpoint on the backend and call it from the frontend:

**On the Backend (NestJS):**
(You can add this to the existing `NotificationsController` if needed later)
```typescript
@Post('admin/send')
@UseGuards(RolesGuard)
@Roles(UserRole.ADMIN)
async adminSendNotification(@Body() dto: { userId: string, title: string, message: string }) {
  return this.notifications.createAndSend({
    userId: dto.userId,
    title: dto.title,
    message: dto.message,
    type: 'SYSTEM_ALERT'
  });
}
```

**On the Admin Portal (React):**
```tsx
const sendCustomPush = async (userId, title, message) => {
  await axios.post('YOUR_BACKEND_URL/notifications/admin/send', 
    { userId, title, message },
    { headers: { Authorization: `Bearer ${adminToken}` } }
  );
  alert('Push notification sent to user!');
};
```

## Summary
1. Initialize the NativeNotify SDK in your app root.
2. Call `registerIndieID(userId, APP_ID, APP_TOKEN)` on login.
3. Call `deleteIndieID(userId, APP_ID, APP_TOKEN)` on logout.
4. Fetch historical data via `GET /notifications` from the backend.
5. **All core features** (Deposits, Withdrawals, Transfers, KYC, Tickets, Time Deposits, and Messages) automatically trigger push notifications from the backend.
